# Русификатор HoN под Linux

Порт установки на Linux (Proton / Wine). Ставит **только перевод** - без
фонового агента, обращений в сеть и баннеров, которые есть в Windows-установщике.

## Как это работает

Перевод - это пять текстовых файлов в `bundle/`. Движок K2 при старте грузит
`/stringtables/interface.str`, `/stringtables/entities.str` и т.д., подставляя
суффикс локали из `host_locale`. В `resources0.jz` лежат только `*_en.str` и
`*_th.str`, поэтому при `host_locale "en"` запрос резолвится в `*_en.str`.

Файлы на диске в `<игра>/stringtables/` движок читает в обход архива, так что
`resources0.jz` (8.5 ГБ) не трогается: бэкап не нужен, откат - удаление
нескольких файлов. Поэтому же локаль остаётся `en`, а не `ru` - русский текст
подменяет собой английский. Имена героев, предметов и способностей в переводе
намеренно оставлены английскими.

### Почему просто скопировать файлы недостаточно

Лаунчер Juvio при каждом запуске сверяет состав каталога игры со своим
манифестом (`cache/*.bin`, protobuf со списком файлов и их размеров). Любой
файл, которого в манифесте нет, он считает признаком битой установки:
показывает "требуется обновление", а нажатие "обновить" вычищает каталог.

Поэтому во время проверок лаунчера перевода в каталоге быть не должно.
Режим `--on-launch` ждёт в логе апдейтера строку `Delegating to the entry
point` - она означает, что проверки позади и управление уходит движку, -
и только тогда раскладывает файлы. Движок открывает каталог примерно через
100 мс после этого, так что запас есть. После выхода из игры файлы убираются,
чтобы следующий запуск лаунчера снова прошёл чисто.

Замеры inotify на живом запуске (`--probe`):

```
+0.099s  open   (каталог stringtables)
+0.120s  open/read  interface.str
+0.130s  open/read  interface_en.str
+0.190s  open/read  client_messages.str / _en.str
+1.126s  open/read  entities.str, game_messages.str
```

Попытки удерживать файлы в каталоге силой (фоновый watcher, восстанавливающий
их после зачистки) приводят к тому, что апдейтер не может свести каталог с
манифестом и зацикливается на "требуется обновление". Так устроена Windows-версия
апстрима (`FileSystemWatcher`) - на лаунчере 0.12.8.1 этот подход уже не
работает.

## Установка

Пропиши скрипт в Launch Options ярлыка в Steam
(ПКМ по игре -> Свойства -> Параметры запуска):

```
bash -c '/путь/до/HoN_RU_Pack/linux/apply.sh --on-launch & exec "$@"' -- %command%
```

Скрипт стартует в фоне вместе с игрой, дожидается конца проверок лаунчера,
раскладывает перевод и убирает его после выхода из игры.

Префикс ищется сам: `compatdata/*/pfx` во всех библиотеках Steam (включая
flatpak и дополнительные из `libraryfolders.vdf`), `$WINEPREFIX`,
`$STEAM_COMPAT_DATA_PATH`, `~/.wine`, префиксы Lutris и Bottles. Внутри
префикса перебираются все `drive_c/users/*` - под Proton это `steamuser`,
в остальных случаях имя системного пользователя.

Нужны `python3` и `pgrep`.

Запустить вручную, чтобы проверить:

```sh
./linux/apply.sh --on-launch     # затем запусти игру обычным способом
./linux/apply.sh --probe         # то же плюс лог обращений движка к файлам
```

Это замена фонового агента Windows-версии - без резидентного процесса в
памяти, без автозапуска при входе в систему и без походов на GitHub.

> Голый `./linux/apply.sh` без флагов просто раскладывает файлы и выходит.
> Так делать не стоит: следующий запуск лаунчера увидит их и потребует
> обновление. Режим оставлен для отладки.

### Если игра не нашлась

Создай `linux/config.local.sh` (он в `.gitignore`):

```sh
HON_GAME_DIR="/путь/до/AppData/Local/Juvio/heroes of newerth"
HON_DOCS_DIR="/путь/до/Documents/Juvio/Heroes of Newerth"
```

## Удаление

```sh
./linux/uninstall.sh
```

Удаляет разложенные файлы, возвращает `startup.cfg` из бэкапа
(`startup.cfg.honru-bak`). После этого убери скрипт из Launch Options.

Если лаунчер вдруг зациклился на "требуется обновление" - значит в каталоге
игры остались файлы перевода (например, скрипт сняли до того, как он прибрался).
`uninstall.sh` это чинит.

## Переопределение строк

`overrides.str` - правки поверх `bundle/`, накладываются на лету при установке.
Файлы `bundle/` остаются нетронутой копией апстрима, поэтому обновления
перевода подтягиваются без конфликтов слияния.

Формат: `<файл>:<ключ><TAB><значение>`, комментарии через `//`.

Сейчас там две строки: апстрим подменяет `main_label_username` и
`main_login_remember_me_tip` (подпись поля "Имя пользователя" и подсказка
галочки "запомнить меня" на экране входа) версией пакета и ссылкой на Boosty -
оверрайд возвращает им исходный смысл.

## Отличия от Windows-установщика апстрима

| | Апстрим | Здесь |
|---|---|---|
| Раскладка `.str` | да | да |
| `host_locale` -> `en` | да | да |
| Резидентный агент с FileSystemWatcher | да | нет, вместо него окно после проверок лаунчера |
| Проверка версии на GitHub раз в 12 ч | да | нет |
| Баннер `ui_login_banner` | да | нет |
| MOTD с рекламой в `interface_en.str` | да | нет |
| Сброс `login_refreshToken` (разлогин) | да | нет |

Ещё одно расхождение: установщик апстрима перезаписывает `startup.cfg` в
UTF-8, тогда как игра хранит его в UTF-16LE. `apply.sh` определяет кодировку
по BOM и сохраняет исходную.
