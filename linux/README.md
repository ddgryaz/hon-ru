# Как устроен порт под Linux

Установка и команды - в [корневом README](../README.md). Здесь только механика
и грабли, на которые мы наступили.

## Почему просто скопировать файлы недостаточно

Лаунчер Juvio при каждом запуске сверяет состав каталога игры со своим
манифестом (`cache/*.bin`, protobuf со списком файлов и их размеров). Любой
файл, которого в манифесте нет, он считает признаком битой установки:
показывает "требуется обновление", а нажатие "обновить" вычищает каталог.

Значит, во время проверок лаунчера перевода в каталоге быть не должно. Режим
`--on-launch` ждёт в логе апдейтера строку `Delegating to the entry point` -
она означает, что проверки позади и управление уходит движку, - и только тогда
раскладывает файлы. После выхода из игры файлы убираются, чтобы следующий
запуск лаунчера снова прошёл чисто.

Запас по времени есть: замеры inotify на живом запуске (`make probe`)
показывают, что движок открывает каталог примерно через 100 мс после этой
строки.

```
+0.099s  open   (каталог stringtables)
+0.120s  open/read  interface.str
+0.130s  open/read  interface_en.str
+0.190s  open/read  client_messages.str / _en.str
+1.126s  open/read  entities.str, game_messages.str
```

Попытки удерживать файлы в каталоге силой приводят к тому, что апдейтер не
может свести каталог с манифестом и зацикливается на "требуется обновление".
Так был устроен Windows-установщик исходного проекта (`FileSystemWatcher`) -
на лаунчере 0.12.8.1 этот подход уже не работает.

## Какие файлы читает движок

Перевод - это пять текстовых файлов в `bundle/`. Движок K2 при старте грузит
`/stringtables/interface.str`, `/stringtables/entities.str` и так далее,
подставляя суффикс локали из `host_locale`. В `resources0.jz` лежат только
`*_en.str` и `*_th.str`, поэтому при `host_locale "en"` запрос резолвится
в `*_en.str`.

Файлы на диске в `<игра>/stringtables/` движок читает в обход архива, так что
`resources0.jz` (8.5 ГБ) не трогается: бэкап не нужен, откат сводится к
удалению нескольких файлов.

Локаль остаётся `en`, а не `ru`, именно потому, что русский текст подменяет
собой английский.

## Почему файл собирается заново, а не копируется

Файл на диске подменяет архивный **целиком** - отката к архиву по отсутствующим
ключам нет. Поэтому `apply.sh` не копирует `bundle/` как есть, а собирает файл
заново: берёт базу из `resources0.jz` и накладывает сверху русские значения.

Иначе каждый ключ, которого нет в `bundle/` (а игра добавляет их с каждым
патчем), исчезал бы из интерфейса вместе с английским текстом. Выглядит это как
предметы без описания.

Побочный плюс: новые строки из патчей игры подхватываются сами, на английском,
а не пропадают.

По той же причине пустые значения в `bundle/` игнорируются - иначе они затёрли
бы английский текст пустотой.

## Где ищется игра

Префикс ищется сам: `compatdata/*/pfx` во всех библиотеках Steam (включая
flatpak и дополнительные из `libraryfolders.vdf`), `$WINEPREFIX`,
`$STEAM_COMPAT_DATA_PATH`, `~/.wine`, префиксы Lutris и Bottles. Внутри
префикса перебираются все `drive_c/users/*` - под Proton это `steamuser`,
в остальных случаях имя системного пользователя.

Не нашлось - задай пути руками через `linux/config.local.sh`, см. корневой
README.

> Голый `./linux/apply.sh` без флагов просто раскладывает файлы и выходит.
> Так делать не стоит: следующий запуск лаунчера увидит их и потребует
> обновление. Режим оставлен для отладки.

## Отличия от установщика исходного проекта

Перевод основан на [Xyling12/HoN_RU_Pack](https://github.com/Xyling12/HoN_RU_Pack).
Его Windows-установщик делал больше, чем нужно для перевода:

| | Исходный проект | Здесь |
|---|---|---|
| Раскладка `.str` | да | да |
| `host_locale` -> `en` | да | да |
| Резидентный агент с FileSystemWatcher | да | нет, вместо него окно после проверок лаунчера |
| Проверка версии на GitHub раз в 12 ч | да | нет |
| Баннер `ui_login_banner` | да | нет |
| MOTD с рекламой в `interface_en.str` | да | нет |
| Сброс `login_refreshToken` (разлогин) | да | нет |

Ещё одно расхождение: тот установщик перезаписывал `startup.cfg` в
UTF-8, тогда как игра хранит его в UTF-16LE. `apply.sh` определяет кодировку
по BOM и сохраняет исходную.
