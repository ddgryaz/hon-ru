# Как устроен порт под Linux

Установка и команды - в [корневом README](../README.md).

## Когда раскладываются файлы

Лаунчер сверяет каталог игры со своим манифестом и на любой лишний файл
отвечает "требуется обновление". Поэтому во время его проверок перевода в
каталоге быть не должно.

Режим `--on-launch` ждёт в логе апдейтера строку `Delegating to the entry
point` (проверки позади, управление уходит движку) и только тогда кладёт файлы
в `<игра>/stringtables/`. Движок открывает их примерно через 100 мс после этой
строки (замер `make probe`). После выхода из игры файлы убираются.

Голый `./linux/apply.sh` без флагов раскладывает файлы и выходит. Только для
отладки: следующий запуск лаунчера потребует обновление.

## Почему не мод

Движок умеет подключать перевод модом (`-mod "heroes of newerth;extensions"`),
и лаунчер его не проверяет. Но с любым `-mod` движок не находит готовый кеш
шейдеров из `resources0.jz` и компилирует шейдеры сам. Под Proton компилятор
Wine часть из них не собирает, и эффекты рисуются квадратами.

## Почему строки собираются заново

Файл на диске подменяет архивный целиком. Если копировать `bundle/` как есть,
ключи, которых в нём нет, пропадут из игры. Поэтому база берётся из
`resources0.jz` установленной игры, а сверху накладываются русские значения.
Новые строки из патчей так остаются на английском, а не исчезают.

Локаль остаётся `en`: русский текст подменяет английский, локали `ru` в игре
нет.

## Где ищется игра

Префиксы Proton во всех библиотеках Steam (включая flatpak), `$WINEPREFIX`,
`$STEAM_COMPAT_DATA_PATH`, `~/.wine`, Lutris и Bottles. Не нашлась - задай
пути в `linux/config.local.sh`, см. корневой README.
